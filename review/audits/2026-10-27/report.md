# Delb repository audit

Audit date: October 27, 2026, America/New_York. Baseline: `10141146ab3f21a4201ca87812049a23a01871a9`.

## Assessment

The highest priorities are authorization and preserving original files during failed operations. Two live API paths let an ordinary signed-in user gain access to a book they could not previously read. A browser test also showed an uploaded EPUB script modifying its parent application page. Independent filesystem probes reproduced destructive failure handling in canonical moves and Dropbox ingest. These deserve attention before a cosmetic or architectural cleanup.

This report contains **37 prioritized findings**, including one unmeasured performance opportunity. No application fixes were implemented. The original checkout was clean at the start. Only this report and its audit evidence were added. Production books, databases, environment files, and the personal browser profile were excluded from runtime checks.

The existing tests provide useful protection for EPUB cover editing, sorting, themes, sanitization, and fullscreen behavior. All **139 existing test cases** passed, including subtests. They do not cover several of the failures below. A green test run therefore does not establish authorization or data-loss safety.

## Method and definition of done

The workflow was to inventory the repository, partition server/storage/client review, verify important findings independently, exercise a disposable instance, deduplicate findings, and produce an ordered repair backlog. The Prove It Works principle required independent probe reruns and direct API/browser observations instead of accepting a green build as proof. Type System Discipline guided the review of untrusted paths, numeric contracts and state invariants.

Completion means every requested audit category has a recorded coverage level, actionable findings have evidence and a remedy, and verification gaps are explicit. It does not mean every line or possible interleaving has been proved correct.

The inventory contained 452 tracked files. Application/server/EPUB source and colocated test inventory contained 204 files, approximately 53,000 lines. Review depth varied. Important flows received targeted source tracing and executable probes; other files received inventory, compiler/linter/build coverage, or a contextual scan. See [inventory.csv](evidence/inventory.csv). Its review labels are deliberately conservative.

**Evidence labels.** `LIVE API` means observed through the running Nuxt API and disposable SQLite database. `BROWSER` means observed in isolated Chrome. `SOURCE PROBE` means executed actual extracted/transpiled source with controlled boundaries; this is not end-to-end integration coverage. `STATIC` means supported by source tracing without runtime reproduction. `REGISTRY` means reported against the lockfile by the live advisory service. Confidence describes the finding, not the amount of integration testing.

**Priorities.** P1 should be resolved before treating a shared or untrusted library as hardened. P2 is a concrete next repair. P3 is a lower-urgency improvement. No finding is labeled an unauthenticated, unconditional remote compromise.

## P1 findings

### A01. Explicit bulk assignment grants access to an invisible book

**LIVE API, high confidence.** [server/api/collections/[id]/books/bulk.post.ts:230](../../../server/api/collections/[id]/books/bulk.post.ts#L230) accepts explicit `bookIds` without intersecting them with the caller's visible books or the authorized scope. The following inserts make those books visible through a collection the caller controls. Knowing a foreign UUID is sufficient. The probe observed download **404 → assignment 200 → download 200**, with real ZIP bytes from a generated EPUB. UUID obscurity is not an authorization control.

**Impact and remedy.** A user can obtain another user's book. Resolve the selected IDs through an authorized source membership in the same transaction as linking. Verify both explicit and all-in-collection paths, including nonexistent and foreign IDs. Evidence: [download probe](evidence/audit-file-access-results.json).

### A02. Global duplicate matching exposes and then grants private books

**LIVE API, high confidence.** [server/api/books/metadata-import/create.post.ts:491](../../../server/api/books/metadata-import/create.post.ts#L491) and [server/utils/books/duplicates.ts:163](../../../server/utils/books/duplicates.ts#L163) match globally, return private candidates, and allow `use_existing` to link a candidate into the caller's collection. A user can submit title/author metadata, obtain an inaccessible candidate ID from the 409 response, then use it. The probe observed candidate disclosure, resolution 200, and subsequent book access 200.

**Impact and remedy.** This provides both discovery and unauthorized access. Scope duplicate matching and candidate resolution to currently visible books. Audit upload's use of the same helper for private candidate disclosure. Verify that a private match never appears in either response or link resolution. [API evidence](evidence/audit-http-results.json).

### A03. Book scripts execute with the application origin

**BROWSER, high confidence.** [app/pages/books/[id]/read.vue:280](../../../app/pages/books/[id]/read.vue#L280) and [app/pages/books/[id]/read.vue:291](../../../app/pages/books/[id]/read.vue#L291) enable scripted content. Installed epubjs combines `allow-same-origin allow-scripts`. A generated EPUB containing only a harmless script read its parent origin and set a parent-body marker in the actual authenticated `/books/:id/read` page. With scripted content disabled in the fixture, the marker remained absent.

**Impact and remedy.** A malicious imported/shared EPUB can run code in the reader's application context when opened. Disable book scripting by default and test a representative corpus in both modes. If script support is a requirement, isolate it on a separate origin with an explicit communication boundary. The ordinary fixture passed with scripts disabled, but that is not full compatibility clearance. [Browser evidence](evidence/audit-origin-browser-results.json). This confirms a risk already noted in `review/README.md`.

### A04. Canonical file moves discard different contents and failed sidecars

**SOURCE PROBE, high confidence.** [server/utils/books/storage/move/move-book-storage.ts:235](../../../server/utils/books/storage/move/move-book-storage.ts#L235) treats an existing destination as proof of a completed migration and deletes the source without comparing bytes. [server/utils/books/storage/move/move-book-storage.ts:319](../../../server/utils/books/storage/move/move-book-storage.ts#L319) similarly deletes colliding entries; the cleanup at line 338 removes the old directory even after a sidecar rename throws. Probes left the different destination bytes intact while deleting the source, and lost a sidecar after an injected rename error.

**Impact and remedy.** Metadata edits can lose files on collision or move failure. A collision is possible with shortened ID prefixes, a stale destination, or multiple same-format rows converging on one name; the audit did not measure frequency. Refuse nonidentical collisions, track every move, and remove old directories only after verified completion. Test same-format files, collision, EXDEV and partial failure. [Storage proof](evidence/proof-storage.txt).

### A05. Replacement upload deletes the original before committing its replacement

**SOURCE PROBE plus STATIC, high confidence.** [server/api/books/upload.post.ts:238](../../../server/api/books/upload.post.ts#L238) invokes `deleteBook(mode='everything')` before writing/inserting the new book. The probe recorded `oldDeleteCalled=true` followed by an injected database failure. Actual deletion semantics are corroborated by [server/utils/books/delete-book.ts:130](../../../server/utils/books/delete-book.ts#L130); the proof stubbed that call rather than destroying a real database record.

**Impact and remedy.** A failed replacement can lose the original book and related user records. Stage and verify the replacement first, preserve the old ID/relationships where intended, commit database changes atomically, and retire original files only after a recoverable commit. [Storage proof](evidence/proof-storage.txt).

### A06. Failed Dropbox database commit destroys the input

**SOURCE PROBE, high confidence.** [server/utils/books/dropbox/ingest.ts:187](../../../server/utils/books/dropbox/ingest.ts#L187) moves the input into the library. Its failure cleanup at line 275 deletes the moved copy. The watcher then attempts to move a source that no longer exists to `failed`. Injecting a database failure left both input and destination absent.

**Impact and remedy.** A transient database error can permanently lose a dropped book. Preserve or restore the input until commit succeeds; a failed ingest must leave an identifiable recoverable copy. [Storage proof](evidence/proof-storage.txt).

### A07. Lockfile contains advisory-affected parsers and image dependencies

**REGISTRY, high confidence about affected versions; application exploitability not established.** [package.json:48](../../../package.json#L48) through its dependency section and the lockfile include Sharp 0.34.5, epub2 → adm-zip 0.5.18, epubjs → xmldom 0.7.13, and Nuxt toolchain dependencies. The live scan returned 47 advisory records. The two critical records are in the simple-git/argv-parser chain under Nuxt devtools; devtools is disabled in config, so do not treat their registry severity as a demonstrated production endpoint exploit.

**Impact and remedy.** Prioritize dependencies that parse uploaded EPUBs and images, then triage toolchain paths. Maintainer advisories confirm [Sharp's affected image-processing range](https://github.com/advisories/GHSA-f88m-g3jw-g9cj) and [xmldom's affected serialization range](https://github.com/advisories/GHSA-wh4c-j3r5-mjhp). The critical toolchain advisories require unsafe Git inputs or environment conditions: [argv-parser](https://github.com/advisories/GHSA-v5rq-49vh-5v5c), [simple-git](https://github.com/advisories/GHSA-x6jw-m9v5-85vh). Select mutually compatible patched versions, refresh the lockfile, and rerun import/reader/native-image/build checks. Avoid a blind force-upgrade. [Full scan](evidence/audit-dependencies.json).

### A08. CI and Docker select an unsupported Node major

**STATIC plus installed manifest inspection, high confidence.** [Dockerfile:1](../../../Dockerfile#L1) selects Node 20, and [.github/workflows/test.yml:15](../../../.github/workflows/test.yml#L15) does the same. Installed/pinned Nuxt 4.6.0 declares `^22.22.3 || ^24.15.0 || >=26.0.0`; its CLI and Undici also require Node 22 or newer. The successful local build used 22.22.3. No Node 20 build was run, so the exact first failure is unverified.

**Impact and remedy.** The documented CI/container runtime lies outside the dependency support contract. Align Docker, CI, root engines, local setup and README on a supported tested runtime. Verify a clean frozen install and container startup on that runtime.

### A09. Collection editors can demote the owner

**LIVE API, high confidence.** [server/api/collections/[id]/members/index.put.ts:115](../../../server/api/collections/[id]/members/index.put.ts#L115) authorizes an editor, then updates another member without protecting the owner at line 143. The probe changed the owner to viewer, leaving memberships containing an editor and viewer but no owner while `ownerUserId` remained set.

**Impact and remedy.** Owner-only operations become unavailable, and ownership safeguards can be bypassed. Reject generic changes to the owner membership and keep owner transfer transactional. Test editor attempts to demote/remove the owner and assert exactly one owner afterward. [API evidence](evidence/audit-http-results.json).

### A10. Remote-image DNS validation is separate from the connection

**STATIC, high confidence in the gap; no DNS-rebinding exploit run.** [server/utils/books/external-image.ts:55](../../../server/utils/books/external-image.ts#L55) validates results from `dns.lookup`; line 159 subsequently calls `fetch` with the hostname, allowing another resolution. Redirect checking does not bind the actual connection to the validated address. Private-address classification also needs a complete IPv6/mapped-address review.

**Impact and remedy.** An attacker-controlled resolver may direct an authenticated proxy request to an internal service. Pin a validated public address in the actual transport, preserve the original hostname for TLS, and repeat this per redirect. Prove blocked connection attempts with a controlled local resolver/transport harness. This remains an exploitation-verification gap and was already acknowledged in `review/README.md`.

## P3 improvement

**A36. Bound entity-index work before library growth makes it costly. STATIC, high confidence in query shape; performance impact unmeasured.** [server/api/authors/index.get.ts:75](../../../server/api/authors/index.get.ts#L75) and line 110 fetch all visible authors and all associated books. Publisher/series/tag indexes use related eager patterns, and some detail endpoints prefetch every visible book ID before a paginated query. The amount of data grows with the library. Paginate entity summaries and cap preview books in SQL; remove redundant full-ID prefetches. Establish representative response size, query count and memory baselines before choosing indexes or claiming a speedup. This is an improvement opportunity, not a measured performance regression.

## Unresolved hypotheses and intentionally retained behavior

- **R01, active SVG proxy content.** [server/api/books/metadata/cover.get.ts:31](../../../server/api/books/metadata/cover.get.ts#L31) reflects the upstream `image/*` content type and bytes. An attacker-controlled SVG navigated as a same-origin document may execute code. The audit did not run an actual proxy/browser SVG exploit because the disposable server blocked outbound traffic. Verify this boundary separately, then reject active formats or decode/re-encode to a safe raster format and consider restrictive response policy.
- **R02, resource exhaustion.** Multipart upload and epub2 extraction need explicit request/archive limits. Dependency advisories reinforce the concern, but this audit did not send a large payload or prove each framework/dependency limit. Add bounded resource tests rather than running destructive memory experiments against a real library.
- **Re-sharing after legitimate access.** `docs/collections-sharing-rbac.md` explicitly describes sticky visibility through another accessible collection as the current v1 direction. That is a product-policy decision, not the A01/A02 bypass: those probes began with no access at all. Preserve the intended re-sharing behavior while fixing unauthorized introduction.
- **Personal collection startup backfill, owner recovery and historical schema maintenance** warrant concurrency/restart coverage; they were not proved broken beyond the specifically identified owner-bootstrap transition.
- Existing EPUB archive limits, mimetype ordering checks, cover staging/journaling, verified-copy fallback and sanitizer repairs should be retained. Passing tests are positive evidence for their covered behavior, not proof of every integration scenario.

## Architecture and maintainability

Nuxt pages and Pinia stores call Nitro APIs. Better Auth establishes identity; collection membership generally establishes book visibility. SQLite stores shared canonical books and user-specific reading/rating/settings state. Local filesystem operations manage books/covers; Dropbox and Calibre introduce alternate write paths. The independent EPUB package provides cover/archive utilities, while reader and legacy metadata parsing use different dependencies.

The recurring weakness is inconsistent invariants across alternate paths: one mutation checks visibility while another only checks a collection; one status transition maintains ranks while another does not; one storage flow journals changes while another deletes originals first. The useful architectural improvement is to give those invariants a small shared implementation after the individual failing cases are captured. A broad rewrite of the UI or server is not justified by these findings.

The client has several large components, including a roughly 2,650-line book editor, but size alone is not a defect. Extract request ownership, persistence and mutation boundaries where the reproduced races justify it. Preserve the established visual language and functional behavior.
